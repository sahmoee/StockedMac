## Ownership and compatibility

Mac owns library UI, authenticated transport and catalogue decoding. MacStorageSystem owns discovery,
preverification, immutable candidate outboxes and runtime deployment. Producers remain publishers and
Worker catalogue responses; consumers remain StockedMac and the existing cache bridge. No shared
wire fields, household schema, source recipe IDs or production data are migrated. Older clients and
existing queues remain valid. Deploy the server helper with both server scripts, then ship the Mac
app; either side may roll back as one source batch without deleting queues or libraries. StockedMac
remains the final parser/image/approval/publication gate; no direct server-to-iOS publication is added.

## Verification and limits

Native catalogue and transport checks, desktop source-contract tests, StockedMac generic macOS build,
and both offline server suites cover the batch. Desktop UI still needs manual interaction testing.
No metered AI or publisher crawl is run for validation. DNS preflight is defense-in-depth, not a
DNS-pinning/network-sandbox guarantee. Existing OS/network egress controls remain required. Existing
image header validation is not a full hostile-media decoder sandbox.
